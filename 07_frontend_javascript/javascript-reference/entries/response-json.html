이럴 때 사용한다

응답 본문을 데이터로 변환할 때

response.json은 Promise를 반환하고 응답 본문을 JSON으로 파싱한다. JSON.parse와 달리 비동기로 본문을 읽는다. 본문은 보통 한 번만 소비할 수 있어 두 방식이 필요하면 읽기 전에 clone한다.

먼저 구분할 것

json() 뒤에 같은 Response의 text()를 호출하면 이미 소비한 본문이라 실패한다. 잘못된 JSON은 파싱 오류가 된다.

비교 예제 원문: 읽기 전에 clone

JavaScript

// 읽기 전에 clone
async function read() {
  const response = new Response('{"count":2}');
  const copy = response.clone();
  console.log(await response.json());
  console.log(await copy.text());
}
read().catch(error => console.error(error.message));

기대 결과: 객체 {"count":2} → 문자열 {"count":2}

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

json() 뒤에 같은 Response의 text()를 호출하면 이미 소비한 본문이라 실패한다. 잘못된 JSON은 파싱 오류가 된다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
