DOMContentLoaded / load

DOM 파싱 완료와 자원 로딩 완료를 구분한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

DOM 초기화 시점과 전체 자원 준비 시점을 나눌 때

DOMContentLoaded는 이미지 완료를 기다리지 않는다. window load는 종속 자원 로딩을 기다린다. 이미 준비된 문서에 나중에 등록할 때는 readyState를 함께 확인한다.

먼저 구분할 것

이미 DOMContentLoaded가 끝난 문서에 리스너만 추가하면 실행되지 않는다. readyState를 확인하고 바로 호출하는 경로도 둔다.

DOM 준비 로그 뒤 load 완료

console 출력은 오른쪽 결과 창에 표시된다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 현재 준비 상태와 load 시점 비교

JavaScript

// 현재 준비 상태와 load 시점 비교
console.log('스크립트 실행 시점:', document.readyState);
document.addEventListener('DOMContentLoaded', () => console.log('DOMContentLoaded:', document.readyState));
window.addEventListener('load', () => console.log('load:', document.readyState));

기대 결과: 이 body 끝 예제에서는 loading → interactive → complete 순서로 나타난다.

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

이미 DOMContentLoaded가 끝난 문서에 리스너만 추가하면 실행되지 않는다. readyState를 확인하고 바로 호출하는 경로도 둔다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
