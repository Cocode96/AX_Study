AJAX / 부분 갱신

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

목록, 검색 결과와 상태를 페이지 이동 없이 갱신할 때

AJAX는 Asynchronous JavaScript and XML의 약자지만 XML만 사용해야 하는 것은 아니다. JSON을 비롯한 여러 형식을 사용할 수 있다. 보통 fetch나 XMLHttpRequest로 요청하며 AJAX는 별도의 JavaScript 문법이 아니다.

먼저 구분할 것

AJAX가 화면을 자동으로 바꿔주는 것은 아니다. 응답을 읽고 어떤 DOM을 갱신할지 개발자가 작성한다. 기본 예제는 브라우저 내부 data URL을 읽는 오프라인 데모이며 실제 서버 통신이 아니다.

기대 결과

목록 불러오기를 누르면 HTML, JavaScript 항목이 나타나고 페이지는 이동하지 않는다.

버튼, 입력 등은 오른쪽 미리보기에서 직접 조작한다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 갱신 중에도 입력한 글은 유지

HTML / CSS

<label>유지할 입력 <input id="keep" placeholder="글을 적고 불러오기"></label><button id="load" type="button">부분 갱신</button><p id="result"></p>

JavaScript

// 갱신 중에도 입력한 글은 유지
const url = 'data:application/json,' + encodeURIComponent(JSON.stringify([
  { id: 1, name: 'HTML' }, { id: 2, name: 'JavaScript' }
]));
document.querySelector('#load').addEventListener('click', async () => {
  try {
    const response = await fetch(url);
    const items = await response.json();
    document.querySelector('#result').textContent = items.map(item => item.name).join(', ');
    console.log('부분 갱신 완료');
  } catch (error) { console.error(error.message); }
});

기대 결과: 입력한 글은 유지되고 결과 문구만 HTML, JavaScript로 바뀐다.

실제 서버에 연결할 때

같은 흐름에서 요청 URL을 바꾼다

위 기본 예제의 data URL은 브라우저 내부 데이터다. 실제 서버 요청은 HTTP로 열린 페이지에서 아래처럼 API URL을 사용한다. 아래 코드는 서버 연결용 참고 코드이며 자동 실행하지 않는다. API는 [{"name":"HTML"}, {"name":"JavaScript"}] 형태의 JSON 배열을 반환한다고 가정한다.

async function loadFromServer() {
  const response = await fetch('/api/items');
  if (!response.ok) throw new Error('HTTP ' + response.status);
  const items = await response.json();
  const nodes = items.map(item => {
    const li = document.createElement('li');
    li.textContent = item.name;
    return li;
  });
  document.querySelector('#list').replaceChildren(...nodes);
}
loadFromServer().catch(error => {
  document.querySelector('#status').textContent = error.message;
});

실제 API 주소와 응답 구조를 확인해 맞춘다. 다른 출처의 서버에는 서버 측 CORS 허용이 필요하다. mode: 'no-cors'로 JSON을 읽을 수 있게 되는 것은 아니다.

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

AJAX가 화면을 자동으로 바꿔주는 것은 아니다. 응답을 읽고 어떤 DOM을 갱신할지 개발자가 작성한다. 기본 예제는 브라우저 내부 data URL을 읽는 오프라인 데모이며 실제 서버 통신이 아니다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
