stopPropagation / stopImmediatePropagation

이벤트 전파나 같은 대상의 다음 핸들러를 멈춘다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

중첩 UI에서 부모 반응 또는 같은 대상의 다음 반응을 막을 때

stopPropagation은 다른 노드로의 전파를 멈추지만 같은 노드의 다른 핸들러는 계속 실행한다. stopImmediatePropagation은 그 핸들러도 막는다. 기본 동작 취소는 별개다.

먼저 구분할 것

이미 실행된 조상 capture 핸들러는 되돌릴 수 없다. 같은 노드의 다음 핸들러까지 막으려면 stopImmediatePropagation을 쓴다.

01 / SYNTAX

문법과 값의 흐름

event.stopPropagation(); event.stopImmediatePropagation();
입력 / 조건
현재 이벤트의 event 객체
결과 / 반환값
전파를 멈추며 반환값은 undefined
원본 / 상태 변경
전파 상태만 변경하며 기본 동작은 취소하지 않는다.

실행 결과

기대 결과

자식 첫 핸들러 → 자식 두 번째 핸들러. 부모 버블은 없다.

버튼, 입력 등은 오른쪽 미리보기에서 직접 조작한다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 같은 노드의 다음 핸들러도 중단

HTML / CSS

<div id="outer" style="padding:24px;border:2px solid #137c68"><button id="child" type="button">전체 중단 비교</button></div>

JavaScript

// 같은 노드의 다음 핸들러도 중단
const outer = document.querySelector('#outer');
const child = document.querySelector('#child');
outer.addEventListener('click', () => console.log('부모 capture는 이미 실행'), true);
child.addEventListener('click', event => {
  console.log('첫 핸들러');
  event.stopImmediatePropagation();
});
child.addEventListener('click', () => console.log('두 번째는 실행 안 됨'));
outer.addEventListener('click', () => console.log('부모 bubble도 실행 안 됨'));

기대 결과: 부모 capture는 이미 실행 → 첫 핸들러

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

이미 실행된 조상 capture 핸들러는 되돌릴 수 없다. 같은 노드의 다음 핸들러까지 막으려면 stopImmediatePropagation을 쓴다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
