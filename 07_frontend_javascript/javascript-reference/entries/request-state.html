기대 결과

이전 느린 요청 뒤 새 빠른 요청을 누르면 새 결과가 유지되고 이전 결과는 무시된다.

버튼, 입력 등은 오른쪽 미리보기에서 직접 조작한다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 버튼 비활성화로 중복 동작 방지

HTML / CSS

<button id="load" type="button">요청</button>

JavaScript

// 버튼 비활성화로 중복 동작 방지
const button = document.querySelector('#load');
button.addEventListener('click', async () => {
  if (button.disabled) return;
  button.disabled = true; button.textContent = '처리 중...';
  try {
    await new Promise(resolve => setTimeout(resolve, 300));
    console.log('한 번 처리');
  } finally {
    button.disabled = false; button.textContent = '다시 요청';
  }
});

기대 결과: 처리 중에는 버튼 비활성화, 완료 뒤 다시 요청 가능

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

예전 요청의 finally가 새 요청의 로딩 상태를 지울 수도 있다. 결과 표시와 로딩 정리 모두 최신 식별자를 확인한다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
