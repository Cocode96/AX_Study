이럴 때 사용한다

실제 API에 데이터를 요청하거나 결과를 받아올 때

fetch는 Response로 이행되는 Promise를 반환한다. 응답 헤더를 받은 뒤 본문을 json/text 등으로 별도 읽는다. 실제 서버는 CORS 정책과 인증, HTTP 상태를 함께 고려한다. 이 예제는 로컬 data URL을 읽는다.

먼저 구분할 것

404/500은 fetch 자체의 reject 조건이 아니다. response.ok를 검사한다. 실제 서버 예제는 주소와 CORS 설정을 확인해야 하며 file://에서 주변 파일을 읽는 것은 브라우저에 따라 제한된다.

console 출력은 오른쪽 결과 창에 표시된다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: text로 읽으면 JSON도 문자열이다

JavaScript

// text로 읽으면 JSON도 문자열이다
async function load() {
  const response = await fetch('data:application/json,%7B%22count%22%3A2%7D');
  const text = await response.text();
  console.log(text, typeof text);
  console.log(JSON.parse(text).count);
}
load().catch(error => console.error(error.message));

기대 결과: {"count":2} string → 2

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

404/500은 fetch 자체의 reject 조건이 아니다. response.ok를 검사한다. 실제 서버 예제는 주소와 CORS 설정을 확인해야 하며 file://에서 주변 파일을 읽는 것은 브라우저에 따라 제한된다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
