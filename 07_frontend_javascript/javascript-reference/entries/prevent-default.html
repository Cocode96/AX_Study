preventDefault

링크 이동이나 폼 제출 같은 기본 동작을 취소한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

폼의 페이지 이동이나 링크의 기본 이동을 취소할 때

전파를 멈추지는 않는다. cancelable이 false이거나 passive 핸들러이면 취소되지 않는다. 폼은 버튼 click보다 form submit에서 처리하면 Enter 제출도 처리할 수 있다.

먼저 구분할 것

preventDefault와 stopPropagation을 혼동하지 않는다. return false는 addEventListener 핸들러에서 기본 동작 취소 의미가 없다.

01 / SYNTAX

문법과 값의 흐름

event.preventDefault();
입력 / 조건
취소 가능한 이벤트의 event 객체
결과 / 반환값
취소되면 defaultPrevented가 true가 된다.
원본 / 상태 변경
기본 동작을 취소하지만 전파는 계속된다.

제출 후 페이지 이동 없이 이름과 true 출력

버튼, 입력 등은 오른쪽 미리보기에서 직접 조작한다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 기본 동작 취소 후에도 부모는 받는다

HTML / CSS

<div id="outer"><a id="link" href="#destination">링크 누르기</a></div><p id="destination">목적지</p>

JavaScript

// 기본 동작 취소 후에도 부모는 받는다
const outer = document.querySelector('#outer');
outer.addEventListener('click', () => console.log('부모에도 전달'));
document.querySelector('#link').addEventListener('click', event => {
  event.preventDefault();
  console.log('링크 이동 취소:', event.defaultPrevented);
});

기대 결과: 링크 이동 취소: true → 부모에도 전달

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

preventDefault와 stopPropagation을 혼동하지 않는다. return false는 addEventListener 핸들러에서 기본 동작 취소 의미가 없다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
