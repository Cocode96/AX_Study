JAVASCRIPT / 01

script / defer

HTML에 JavaScript를 연결하고 실행 시점을 정한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

HTML 요소를 찾는 코드와 외부 JS 파일을 연결할 때

외부 일반 스크립트의 defer는 HTML 파싱 후, DOMContentLoaded 전에 실행한다. async는 다운로드가 끝나면 실행하므로 DOM 준비나 파일 간 순서를 보장하지 않는다. 이 미리보기는 body 끝에서 실행한다.

먼저 구분할 것

요소가 null이면 경로 오류와 DOM 생성 전 실행 여부를 먼저 확인한다. 인라인 일반 스크립트에는 defer가 적용되지 않는다.

01 / SYNTAX

문법과 값의 흐름

<script src="app.js" defer></script>
입력 / 조건
src는 JS 경로, defer는 외부 일반 스크립트에 쓰는 불리언 속성
결과 / 반환값
HTML 파싱 후 문서 순서대로 실행한다.
원본 / 상태 변경
스크립트가 수행하는 동작에 따라 다르다.

기대 결과

문구가 “HTML을 읽은 뒤 JavaScript 실행”으로 바뀐다.

버튼, 입력 등은 오른쪽 미리보기에서 직접 조작한다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 준비 상태를 확인한 뒤 실행

HTML / CSS

<p id="message">대기 중</p>

JavaScript

// 준비 상태를 확인한 뒤 실행
// 이미 파싱이 끝난 문서에서도 init을 호출한다.
function init() {
  document.querySelector('#message').textContent = 'DOM 준비 완료';
  console.log('요소를 찾았나요?', !!document.querySelector('#message'));
}
if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', init, { once: true });
} else {
  init();
}

기대 결과: DOM 준비 완료, true

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

요소가 null이면 경로 오류와 DOM 생성 전 실행 여부를 먼저 확인한다. 인라인 일반 스크립트에는 defer가 적용되지 않는다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
