이럴 때 사용한다

Enter 확정, 단축키와 키 눌림 상태를 처리할 때

key는 입력 의미, code는 물리 키 위치를 표현한다. 한글 조합 중 Enter 처리는 isComposing을 확인한다. 길게 누르면 keydown이 반복되므로 단발 동작에는 repeat도 확인한다.

먼저 구분할 것

한글 입력 중 Enter와 일반 Enter를 구분하려면 isComposing을 확인한다. 입력 의미와 물리 키 위치는 key/code가 다르다.

01 / SYNTAX

문법과 값의 흐름

event.key; event.code; event.repeat; event.isComposing
입력 / 조건
key, code, repeat, isComposing, modifier 키 상태
결과 / 반환값
keydown은 눌림, keyup은 놓임. 길게 누르면 keydown이 반복될 수 있다.
원본 / 상태 변경
원하는 단축키에서만 기본 동작을 선택적으로 취소한다.

기대 결과

Enter 입력 시 keydown → Enter 확정 → keyup

버튼, 입력 등은 오른쪽 미리보기에서 직접 조작한다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: Ctrl 또는 Command 조합 감지

HTML / CSS

<label>Ctrl+Enter <input id="input" placeholder="여기에 포커스를 두고 단축키"></label>

JavaScript

// Ctrl 또는 Command 조합 감지
document.querySelector('#input').addEventListener('keydown', event => {
  if (event.isComposing || event.repeat) return;
  if ((event.ctrlKey || event.metaKey) && event.key === 'Enter') {
    event.preventDefault();
    console.log('수정 내용 확정 단축키');
  }
});

기대 결과: Ctrl+Enter 또는 Command+Enter에만 수정 내용 확정 단축키 출력

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

한글 입력 중 Enter와 일반 Enter를 구분하려면 isComposing을 확인한다. 입력 의미와 물리 키 위치는 key/code가 다르다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
