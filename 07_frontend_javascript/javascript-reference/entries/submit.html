브라우저 API

DOM과 이벤트는 브라우저가 제공하는 기능이다.

JavaScript/입력과 브라우저 이벤트

BROWSER API / 60

submit / FormData / requestSubmit

버튼과 Enter 제출을 폼 단위에서 처리한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

폼의 버튼과 Enter 제출을 하나의 처리로 묶을 때

FormData는 name이 있는 제출 대상 폼 컨트롤을 수집한다. disabled 컨트롤과 체크되지 않은 체크박스는 제외한다. requestSubmit은 검증과 submit 이벤트를 거치고 submit() 메서드는 이를 건너뛴다.

먼저 구분할 것

name이 없거나 disabled인 컨트롤은 수집 대상이 아니다. FormData 생성 자체가 폼 유효성 검사를 수행하는 것은 아니다.

01 / SYNTAX

문법과 값의 흐름

form.addEventListener("submit", handler); new FormData(form)
입력 / 조건
submit 이벤트와 form 요소, FormData(form)
결과 / 반환값
검증을 통과하면 submit 핸들러가 실행된다. FormData 값은 문자열 또는 File
원본 / 상태 변경
preventDefault로 기본 제출을 취소하고 결과 UI를 갱신한다.

기대 결과

빈 이름은 검증에서 막히고 이름 입력 후 Enter는 제출 완료

버튼, 입력 등은 오른쪽 미리보기에서 직접 조작한다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: requestSubmit도 검증과 이벤트를 거친다

HTML / CSS

<form id="form"><label>이름 <input name="name" required></label><button type="submit">일반 제출</button></form><button id="request" type="button">requestSubmit 호출</button>

JavaScript

// requestSubmit도 검증과 이벤트를 거친다
const form = document.querySelector('#form');
form.addEventListener('submit', event => {
  event.preventDefault();
  console.log('submit:', new FormData(form).get('name'));
});
document.querySelector('#request').addEventListener('click', () => form.requestSubmit());

기대 결과: 빈 입력은 두 방식 모두 제출되지 않는다. 이름 입력 후 두 방식 모두 submit 로그가 나온다.

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

name이 없거나 disabled인 컨트롤은 수집 대상이 아니다. FormData 생성 자체가 폼 유효성 검사를 수행하는 것은 아니다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
