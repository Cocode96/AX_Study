Promise / then / catch / finally

나중에 완료될 작업의 성공과 실패를 표현한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

완료 시점이 나중인 작업을 단계별로 연결할 때

Promise는 pending, fulfilled, rejected 상태를 가진다. then은 새 Promise를 반환하며 그 안의 반환값과 오류가 다음 단계로 이어진다. finally는 종료 정리에 쓰고 성공값을 첫 인수로 받지 않는다.

먼저 구분할 것

then에서 새 Promise를 반환하지 않으면 다음 단계가 그 작업의 완료를 기다리지 않는다. 이 예제의 타이머는 서버 요청을 흉내 낸 지연일 뿐이다.

실행 결과

기대 결과

동기 코드가 먼저 출력되고 준비된 값 → 가공: 준비된 값 → 정리가 이어진다.

console 출력은 오른쪽 결과 창에 표시된다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 실패가 catch로 전달

JavaScript

// 실패가 catch로 전달
Promise.resolve('첫 단계')
  .then(() => { throw new Error('처리 실패'); })
  .then(() => console.log('실행되지 않음'))
  .catch(error => console.warn(error.message))
  .finally(() => console.log('실패해도 정리'));

기대 결과: 처리 실패 → 실패해도 정리. 실행되지 않음은 출력되지 않는다.

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

then에서 새 Promise를 반환하지 않으면 다음 단계가 그 작업의 완료를 기다리지 않는다. 이 예제의 타이머는 서버 요청을 흉내 낸 지연일 뿐이다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
