클로저

함수가 생성될 때의 바깥 변수에 계속 접근한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

각 버튼이나 인스턴스의 독립 상태를 함수 안에 보관할 때

클로저는 값의 복사본이 아니라 해당 변수에 접근한다. 독립적인 함수 호출은 각각 다른 환경을 만든다. 이벤트 핸들러에서 상태를 유지할 때 활용한다.

먼저 구분할 것

바깥 변수의 현재 값을 읽는다는 점을 놓치지 않는다. 생성 당시 값이 자동 복사되는 것은 아니다.

JavaScript

// 클로저는 현재 값을 읽는다
let name = '처음';
const read = () => name;
name = '변경';
console.log(read());
const snapshot = name;
name = '다시 변경';
console.log(read(), snapshot);

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

바깥 변수의 현재 값을 읽는다는 점을 놓치지 않는다. 생성 당시 값이 자동 복사되는 것은 아니다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
