AbortController / 요청 취소

진행 중 요청을 취소하고 취소를 일반 오류와 구분한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

검색어가 바뀌거나 화면을 떠날 때 이전 요청을 취소할 때

AbortController의 signal을 fetch에 전달하면 abort로 해당 작업을 취소할 수 있다. 취소한 signal은 다시 사용할 수 없다. 새로운 요청에는 새 컨트롤러가 필요하다. 기본 예제는 이미 취소된 signal로 fetch를 시작한다.

먼저 구분할 것

취소는 서버 변경 작업의 롤백이 아니다. 취소 뒤에는 새 컨트롤러를 사용하고 signal.aborted 또는 오류 종류로 일반 실패와 구분한다.

요청 취소됨: AbortError

console 출력은 오른쪽 결과 창에 표시된다. 수정 후 실행하거나 Ctrl+Enter를 누른다. 수정 내용은 파일에 자동 저장되지 않는다.

비교 예제 원문: 취소한 signal은 다시 쓰지 않는다

JavaScript

// 취소한 signal은 다시 쓰지 않는다
const previous = new AbortController();
previous.abort();
const next = new AbortController();
console.log('이전 signal:', previous.signal.aborted);
console.log('새 signal:', next.signal.aborted);

기대 결과: 이전 signal: true → 새 signal: false

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

취소는 서버 변경 작업의 롤백이 아니다. 취소 뒤에는 새 컨트롤러를 사용하고 signal.aborted 또는 오류 종류로 일반 실패와 구분한다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
