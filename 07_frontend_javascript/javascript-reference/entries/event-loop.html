동기 코드, Promise 콜백과 타이머의 실행 순서를 구분한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

비동기 코드를 등록 순서대로 실행한다고 오해할 때

Promise의 then 콜백과 await 후속 실행은 마이크로태스크로 처리된다. 현재 작업이 끝난 뒤 마이크로태스크를 처리하며 setTimeout 콜백은 이후 작업에서 실행된다. 타이머를 예약했다고 즉시 실행되는 것은 아니다.

먼저 구분할 것

0ms 타이머도 지금 실행되는 것이 아니다. 긴 동기 루프는 이벤트와 화면 갱신을 막을 수 있다.

JavaScript

// await 이후는 나중에 이어진다
async function task() {
  console.log('A');
  await 0; // 일반 값이어도 후속 실행을 바로 이어가지 않는다.
  console.log('C');
}
task();
console.log('B');

기대 결과: A → B → C

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

0ms 타이머도 지금 실행되는 것이 아니다. 긴 동기 루프는 이벤트와 화면 갱신을 막을 수 있다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
