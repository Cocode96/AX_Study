호출 방식에 따라 함수의 this가 결정되는 것을 확인한다.

주석 있는 예제기본 / 비교 2가지MDN 원문 ↗

이럴 때 사용한다

메서드와 이벤트 핸들러가 사용할 객체를 판단할 때

일반 함수의 this는 호출 방식에 영향을 받는다. 메서드를 분리해 호출하면 원래 객체가 유지되지 않는다. addEventListener의 일반 함수 this는 currentTarget이다. 화살표 함수는 바깥 this를 유지한다.

먼저 구분할 것

메서드를 변수로 꺼내면 원래 객체가 자동 유지되지 않는다. 이벤트에서는 currentTarget을 쓰면 함수 종류에 덜 의존한다.

01 / SYNTAX

문법과 값의 흐름

object.method(); fn.bind(object)
입력 / 조건
함수 호출 방식 또는 bind에 전달한 객체
결과 / 반환값
일반 함수 this는 호출 방식, 화살표 this는 바깥 환경에서 결정된다.
원본 / 상태 변경
bind는 원본 함수 대신 새 함수를 반환한다.

비교 예제 원문: 이벤트 일반 함수의 this

HTML / CSS

<button id="button" type="button">this 확인</button>

JavaScript

// 이벤트 일반 함수의 this
const button = document.querySelector('#button');
button.addEventListener('click', function (event) {
  console.log(this === event.currentTarget);
});
button.addEventListener('click', event => {
  console.log('currentTarget:', event.currentTarget.id);
});

기대 결과: 클릭하면 true / currentTarget: button

03 / TROUBLESHOOTING

이 항목에서 자주 헷갈리는 점

메서드를 변수로 꺼내면 원래 객체가 자동 유지되지 않는다. 이벤트에서는 currentTarget을 쓰면 함수 종류에 덜 의존한다.

오류 메시지로 확인할 위치
ReferenceError
이름 오타, 선언 위치와 선언 전 접근을 확인한다.
TypeError
null이나 undefined인지, 해당 타입에서 호출 가능한 메서드인지 확인한다.
SyntaxError
괄호, 따옴표, 쉼표와 문법을 확인한다. 구문 오류는 예제 실행 전에 표시된다.
